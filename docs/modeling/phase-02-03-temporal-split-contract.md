Phase 2.03 must create deterministic, policy-aware train, validation, and test assignments before any feature preprocessing or model fitting. The split is an experiment-control artifact, not evidence that the current synthetic corpus supports credible temporal generalization.

The canonical corpus exposes a material limitation: first-billing observation time is determined largely by billing frequency. A strict chronological split therefore also separates billing-frequency categories. This is useful for testing failure-safe evaluation mechanics, but it is not a representative model-development sample and must not be repaired by randomizing records.

## Scope

Phase 2.03 includes:

- selecting only eligible observations with an observed binary label;
- assigning observations chronologically by `as_of` using explicit UTC boundaries;
- isolating `policy_id` and outcome episodes across partitions;
- applying a 90-day horizon-overlap embargo;
- producing a versioned, deterministic split manifest;
- reporting included, embargoed, and excluded records and class distributions; and
- failing closed when chronology, isolation, or manifest reproducibility changes.

It does not include feature transformation, imputation, encoding, scaling, selection, resampling, fitting, calibration, threshold selection, or model evaluation. Test labels may be summarized to verify the frozen split, but test features or labels must not influence pipeline choices.

## Population and ordering

The input is the frozen set of observation-contract `1.0.0` records after `validate_observation_records` succeeds.

A record is split-eligible only when:

1. `eligible` is `true`;
2. `label.status` is `observed_positive` or `observed_negative`;
3. `label.value` is `0` or `1`; and
4. all required identity, cutoff, horizon, and label-provenance fields are present and valid.

`right_censored` and `not_applicable` records remain accounted for in the manifest but cannot enter a modeling partition. Input records are normalized to deterministic order by `(as_of, policy_id, observation_id)` before assignment. Caller input order must not affect the result.

## Chronological boundaries and embargo

Boundaries use half-open UTC intervals. For the canonical corpus, the proposed engineering windows are:

| Disposition | `as_of` interval | Purpose |
| --- | --- | --- |
| Train | before `2024-04-01T00:00:00Z` | Earliest labeled observations |
| Embargoed | `2024-04-01T00:00:00Z` through `2024-06-30T23:59:59Z` | Prevent train-label horizons from overlapping validation observations |
| Validation | `2024-07-01T00:00:00Z` through `2024-09-30T23:59:59Z` | Model and preprocessing selection only |
| Calendar gap | `2024-10-01T00:00:00Z` through `2024-11-30T23:59:59Z` | Prevent validation-label horizons from overlapping test observations |
| Test | on or after `2024-12-01T00:00:00Z` | One frozen final assessment |

The implementation must verify the invariant rather than trust the configured dates:

```text
max(train.horizon_end) < min(validation.as_of)
max(validation.horizon_end) < min(test.as_of)
```

Equality is an overlap and must fail. The embargo is based on the complete label horizon, not only the observed outcome timestamp. Records in an embargo or gap are not reassigned to improve class balance.

For future recurring observations, purge every earlier record whose label horizon reaches the next partition and group all rows sharing a policy or outcome episode into only one disposition. A future contract may use explicit episode identifiers; until then, non-null `label.source_event_id` is the outcome-episode key and its ownership must remain unique.

## Canonical diagnostic

Applying the implemented windows to seed `20260817` produces this canonical result:

| Disposition | Records | Negative | Positive | Billing frequency present |
| --- | ---: | ---: | ---: | --- |
| Train | 26 | 13 | 13 | Monthly only |
| Embargoed | 22 | 14 | 8 | Quarterly only |
| Validation | 27 | 12 | 15 | Semiannual only |
| Calendar gap | 0 | 0 | 0 | None |
| Test | 25 | 11 | 14 | Annual only |

These counts must be regenerated by the implementation and committed in the manifest rather than copied as an unchecked constant.

The class counts are adequate for deterministic code-path tests, but the category separation is a severe simulator artifact. The training partition cannot learn coefficients for the held-out billing-frequency values, and billing frequency is also entangled with policy age at first billing. Later synthetic metrics must be labeled as pipeline demonstrations only. Random record splitting, stratified shuffling, moving embargoed quarterly records, or consulting test results to choose different boundaries is prohibited.

## Isolation and leakage assertions

The split builder must reject or fail verification when:

- a `policy_id` appears in more than one of train, validation, or test;
- an `observation_id` receives more than one disposition;
- a non-null label source or future episode identifier appears in multiple partitions;
- a later partition contains an `as_of` earlier than an included prior partition;
- a prior partition's `horizon_end` reaches or crosses the next partition's first `as_of`;
- a censored or ineligible observation enters a modeling partition;
- input reordering changes assignments or serialized bytes;
- the configured contract versions, generator provenance, boundaries, or source-observation digest differ from the manifest; or
- any fitting, learned preprocessing, resampling, calibration, or threshold artifact is supplied to the split step.

Policy isolation is currently trivial because observation contract `1.0.0` emits one row per policy. It is still a required assertion so recurring policy-month observations cannot silently weaken the boundary later.

## Versioned manifest

The proposed canonical artifact is:

```text
docs/experiments/phase-02-03-temporal-split-manifest.json
```

It should contain:

- manifest and split-contract versions;
- observation, label, feature-guard, generator, and event-schema versions;
- seed, policy count, simulation start, and explicit follow-up watermark;
- an SHA-256 digest over canonical source observation identities and temporal fields;
- exact UTC boundaries, interval semantics, horizon length, and embargo rule;
- ordered observation IDs for train, validation, test, embargo, and other exclusions;
- counts by disposition, label status, label value, outcome type, and billing frequency;
- cutoff and horizon ranges for every non-empty disposition;
- policy and outcome-episode overlap counts, all required to be zero; and
- limitations and the `pipeline_engineering_only` decision.

Identity belongs in the split manifest for audit and isolation, but must not enter model features. The manifest must not copy feature payloads. JSON serialization must use sorted keys, stable list ordering, UTF-8, and a trailing newline so `--check` can compare canonical bytes.

| Area | Proposed change |

| Artifact command | Add `scripts/build_temporal_splits.py --write/--check` to regenerate or verify the canonical manifest |
| Tests | Add `simulator/tests/test_temporal_splits.py` covering boundaries, embargo equality, policy and episode overlap, exclusions, order independence, deterministic bytes, and mutation failures |
| Documentation | Add the manifest to `docs/experiments/README.md`, link this contract from `simulator/README.md`, and update `docs/backlog.md` only after checks pass |
| Repository checks | Include manifest verification in the existing `make check` path |

The split module should accept observation records and an explicit split specification. It must not regenerate histories internally, infer a watermark from the last event, or import a modeling library. Generation belongs in the artifact command; deterministic assignment belongs in the reusable library.

## Acceptance gate

Phase 2.03 is complete only when:

1. The canonical manifest is reproducible from documented inputs and commands.
2. Train, validation, and test are chronological and non-empty, with both label classes reported.
3. Policy and outcome-episode overlap across modeling partitions is zero.
4. Horizon-overlap assertions pass strictly between train/validation and validation/test.
5. All embargoed, censored, ineligible, and otherwise excluded records are explicitly accounted for.
6. Mutation tests prove that overlap, duplicate ownership, cutoff equality, and manifest drift fail closed.
7. Reordering input records leaves assignments and canonical manifest bytes unchanged.
8. No fitting, preprocessing, resampling, calibration, threshold selection, or test-guided choice occurs.
9. Documentation prominently records the billing-frequency/time confounding and engineering-only interpretation.
10. `make check` and `git diff --check` pass.

## Downstream boundary

Phase 2.04 may fit learned preprocessing on the train observation IDs only, apply the frozen result to validation and test, and prove that held-out data cannot alter fitted parameters. Model selection may use validation results. Test data remains sealed until the preprocessing contract, candidate models, calibration method, evaluation metrics, and reporting rules are frozen.

If the goal changes from demonstrating pipeline mechanics to making meaningful temporal-performance claims, Phase 2.03 must stop rather than weaken chronology. That goal requires a separately versioned generator and observation design with repeated calendar cohorts, adequate representation of feature categories in the training period, and enough later observations for validation and test.
