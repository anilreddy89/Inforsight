This contract implements the execution boundary assigned to R2-11. It inherits the
approved protocol `2.0.0`, issue-#60 amendment `2.1.0`, and remediation-bound version
`2.2.0`. Historical evidence remains immutable.

## Readiness state transition

The runner first creates the complete 20-seed inventory and evaluates every readiness
rule. Acceptance fitting, prediction, oracle joining, resampling, and metrics are legal
only when every readiness rule passes. Leakage, protected/oracle exposure, scoring
bypass, mismatched shared streams, selective omission, holdout access, or evidence
manipulation is `stop`; other incomplete or failed readiness is `redesign`.

No failed seed or fold is retried, replaced, or omitted. One or two structurally invalid
signal replications remain failures in denominator 20; more than two is `redesign`.

## Frozen execution

- Signal/null pairs use seeds `20261001..20261020`; null changes only
  `signal_scale: 1 -> 0` and shares its stream-set identity.
- Every valid signal replication uses all three frozen acceptance folds, canonical row
  order, fold-local fit-only preprocessing, and purpose-bound acceptance authorization.
- Both candidates run null and policy-vector-shuffle controls. XGBoost alone owns the
  signal, oracle, calibration-sanity, learning, ablation, robustness, and temporal gates.
- Policies are resampling units. Each required interval uses 1,000 deterministic
  bootstrap replicates; fewer than 950 valid replicates is `redesign`.
- Metrics, thresholds, percentile indices, seed-balanced pooling, learning subsets,
  ablations, scenarios, temporal rules, and `1e-12` tolerances are exactly those in the
  approved protocol. Runtime rule evaluation uses full precision.
- Oracle records enter only the dedicated oracle-evaluation boundary after ordinary
  scoring and never enter features, preprocessing, fitting, or ordinary authorization.

## Rule and decision schema

Every rule record contains `rule_id`, `family`, `scope`, `inputs`, `comparator`,
`threshold`, `observed`, `status`, `failure_classification`, and `evidence_digests`.
Missing or non-finite required evidence fails. Decision precedence is `stop`, then
`redesign`, then `proceed`; no waiver or manual override exists.

## Claim and exit boundary

`proceed` means only that the role-isolated synthetic mechanism passed its frozen tests;
the extended selection interval is not a pure prospective backtest. Only a merged
`proceed` resumes P2-08/P2-09. No decision authorizes calibration, thresholds,
explanations, operational action, release claims, or final-holdout access.
